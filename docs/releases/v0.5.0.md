Adds profile-specific HTTP/2 request headers and Chrome 157 Priority reconstruction.

- Each profile selects its HTTP/2 header policy from the shared catalog. Both Chrome 157 profiles order browser headers for navigation, subresources, and POST bodies; custom headers follow in their supplied relative order.
- Add missing `Priority` only after the target connection negotiates HTTP/2. The value follows `Sec-Fetch-Dest`, with `empty` plus `Sec-Fetch-Mode: no-cors` used as the beacon hint. That hint also covers no-cors fetches.
- Retain caller-supplied priorities, including empty values, and preserve header values and duplicate-value order. HTTP/1.1 and WebSocket Upgrade requests retain their existing behavior. Other browser versions keep their preserve policy until measured.
- Keep Go dependencies in Docker build layers so an evicted cache mount cannot break later offline test steps.

Validated in Docker with Go/race tests, 31 backend tests, type checking, lint, unused-code and package checks, pinned Chrome 157 comparisons, and persistent Caido 0.59.0 checks. Tests decode real HTTP/2 header frames, cover concurrent and reused connections through HTTP/SOCKS5 proxies, and compare reconstructed navigation, GET/POST fetch, and form POST headers with the browser.

Linux x86_64 only. Install `plugin_package.zip` through Caido's plugin installer; `plugin_package.zip.sha256` contains its SHA-256 checksum. See the [header policy guide](https://github.com/ahmetdotrun/caido-impersonate-tls/blob/v0.5.0/docs/compatibility.md#http2-request-headers) for the priority table and limits.
